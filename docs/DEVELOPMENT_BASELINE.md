# 合同管理系统开发基线与优化实施计划

版本：v1.0  
状态：已确认，后续开发与验收的统一依据

## 1. 建设目标与边界

- 服务约 40 人的新媒体互联网企业，主要覆盖商务、部门经理、财务、项目执行、总经理和系统管理员。
- 运行入口为手机钉钉和桌面钉钉，优先保证移动端关键流程完整、稳定、可恢复。
- 客户及业务主要包括政企、餐饮、地产等行业的活动策划执行、广告及新媒体、销售业务。
- 采用渐进式交付：先打通可生产运行的端到端闭环，再按优先级增强；不为未确认需求增加复杂设计。
- 生产部署为单应用实例、云 MySQL，不引入 Redis；测试与生产环境隔离，禁止使用生产数据开发测试。

## 2. 角色与数据范围

- 商务：管理本人客户、商机、合同、跟进、回款跟进和开票申请；合同列表显示“我的合同”。
- 部门经理：查看本部门客户、合同、跟进及经营数据；合同列表显示“本部门合同”。
- 财务：查看全部合同及必要客户基础资料，管理回款确认、发票和实际成本；不查看商务详细跟进内容。
- 总经理：查看全部业务和经营数据，参与配置流程中的审批节点；合同列表显示“全部合同”。
- 项目执行：仅查看参与项目的预算及本人相关成本，不默认查看完整经营利润。
- 系统管理员：负责配置和运维，不因管理员身份自动获得业务数据导出权限。
- 敏感信息按角色脱敏；银行信息仅财务、总经理及明确授权人员可查看完整值。

## 3. 已确认业务基线

### 3.1 客户与商机

- 启用轻量商机模块；阶段为：待联系、需求确认、方案报价、商务谈判、合同推进、已成交、已流失。
- 一个客户可有多个商机；商机成交后可直接创建合同，也可先创建项目再创建合同。
- 业务分类为活动服务、广告与新媒体、销售、其他；管理员可新增、停用、排序，已被引用的分类不可删除。
- 一个业务对象只设置一个主业务分类。
- 商务查看本人或共享客户；公海独立管理。部门经理查看本部门客户、联系人和跟进。
- 商务查看他人客户时仅显示客户名称、行业和负责人，可申请共享；负责人审批，负责人不可用或超时由部门经理处理。
- 统一搜索覆盖客户、联系人、商机、合同、项目和供应商，并严格遵循数据权限。
- 统一社会信用代码精确重复时阻止创建；名称相似或手机号精确重复时需管理员确认。
- 下次行动及时间均非必填；15 天未跟进提醒、30 天进入公海候选，均可配置，进入公海须经理确认，不自动释放。
- 跟进记录默认本人 24 小时内可编辑，之后走更正；禁止物理删除，管理员仅可作废并保留审计。规则可配置。

### 3.2 合同、审批、签署与执行

- 默认流程为：提交审批 → 审批完成 → 签署 → 手工进入执行 → 抄送。
- 审批流程可按合同类型、金额、业务分类等配置，可包含部门经理等节点；当前默认最终由总经理审批。
- 流程只允许唯一最高优先级规则命中；同优先级冲突时阻止提交。审批中的实例保留流程快照。
- 驳回必须填写修改要求。
- 合同从草稿提交审批，审批全部通过后自动进入执行；不再设置独立签署或提前执行阶段。
- 纸质原件信息为可选字段。
- 执行抄送支持角色、部门、人员，可配置是否要求确认；一个执行确认人。
- 合同审批通过后进入执行，后续业务调整不在当前产品范围内。
- 变更需上传依据或填写原因，合同编号保持不变并形成 V2、V3 等版本历史。
- 新金额不得小于已开票、已回款或已付款金额。

### 3.3 收付款、发票与项目成本

- 销售合同回款计划、采购合同付款计划的最终合计必须等于合同含税总额。
- 提交审批时允许计划暂不完整，但进入执行前必须补齐。
- 允许暂估合同并参与预测；结算后更新最终金额且保留调整历史。
- 回款提醒默认提前 7、3、1 天及逾期即时提醒；逾期 3 天升级部门经理、7 天升级总经理，天数可配置。
- 商务可记录催款内容、客户承诺、原因和下次跟进；只有财务可以确认到账。
- 发票由商务申请，财务处理开具、红冲和作废；已审批记录不可删除。
- 发票默认关联合同和客户；特殊无合同开票允许通过可配置审批流程处理。
- 有效开票总额不得超过合同含税金额，红冲或作废释放额度；允许先票后款并明确标识。
- 暂估合同允许开票，但累计金额不得超过暂估金额。
- 项目毛利按不含税口径；第一版不分摊正式员工工资，临时人员、劳务、外包成本计入项目成本。
- 无合同小额成本允许关联项目并上传凭证；超过 5000 元需合同或特殊审批，阈值可配置。
- 低毛利默认低于 20% 预警，阈值可配置。

### 3.4 经营分析、导出和审计

- 总经理看板分为经营结果、经营预测、风险、组织四组，并支持风险明细下钻。
- 经营统计排除非交易、已作废和未履行终止合同。
- 商机预测同时展示原始金额和按阶段概率加权金额；排名遵循角色数据范围。
- 导出严格继承页面数据范围并执行字段脱敏；敏感财务导出需独立权限。
- 每次导出记录审计日志；超过 500 条需二次确认，并保存导出人、条件、时间、数量等元数据。

### 3.5 交互与可靠性

- 不同角色进入对应工作首页；低频功能收纳到“更多”。
- 复杂操作使用独立页面，短操作使用弹窗。
- 表单支持本地草稿；弱网提交须保留输入、允许安全重试，并通过幂等机制避免重复数据。
- 手机钉钉和桌面钉钉均须完成角色化验收。

## 4. 非功能与生产基线

- 生产必须使用 MySQL，关闭调试和钉钉模拟模式，启用 HTTPS 与安全 Cookie。
- 应用密钥、JWT 密钥必须使用不少于 32 位的独立随机值，不得写入仓库或日志。
- 每日全量备份保留 30 天；每周生成加密异地备份；每季度执行恢复演练并留档。
- 定时任务、备份、钉钉发送失败时首次发送站内告警，连续 3 次失败升级钉钉告警。
- 发布前必须通过 PHP 自动化测试、前端测试、数据库结构检查、静态质量检查和依赖安全审计。
- 健康探针不得暴露数据库错误、路径、凭据或其他内部实现信息。

## 5. 优化实施顺序

### P0 第一阶段：生产运行基础

1. MySQL 测试环境、初始化与迁移一致性。
2. 生产配置自检、通用健康探针和密钥安全检查。
3. 自动化质量门禁、依赖漏洞审计和发布前检查。
4. 数据库备份、保留策略、异地备份说明、恢复演练流程。
5. 定时任务统一执行、连续失败计数和分级告警。

验收：全量门禁通过；生产自检仅因真实外部配置缺失而失败；备份与恢复流程可执行并可审计。

### P0 第二阶段：合同全生命周期闭环

完善可配置审批、审批通过自动执行、抄送确认、变更版本和状态约束。

验收：销售合同与采购合同均可从创建走到归档；非法状态跳转、流程冲突和金额倒挂均被阻止。

### P0 第三阶段：财务闭环

完善收付款计划、到账确认、催款升级、发票额度、红冲作废和特殊无合同开票。

验收：合同金额、收付款、发票额度并发场景保持一致，财务角色权限正确。

### P1 第四阶段：商务闭环

完善客户、联系人、商机、跟进、公海候选、共享申请、查重和统一搜索。

验收：商务与经理数据范围正确，商机成交可平滑转合同或项目，无客户隐私越权。

### P1 第五阶段：项目经营

完善项目预算、实际成本、无合同成本审批、暂估结算和毛利预警。

验收：不含税收入成本口径一致，各角色只看到授权数据。

### P1 第六阶段：管理分析

完善总经理四组看板、预测、排行、风险下钻、导出和审计。

验收：统计口径可追溯至明细，导出权限、脱敏、二次确认和审计完整。

### P2 第七阶段：体验与性能

完成角色首页、移动端表单、草稿、弱网重试、幂等、查询索引与慢查询治理。

验收：手机及桌面钉钉角色验收通过，关键操作可恢复，常用页面性能达到生产目标。

## 6. 开发与验收规则

- 每阶段严格执行：复现或建立验收用例 → 最小影响实现 → 自动化测试 → 角色验收 → 更新文档。
- 未在本基线确认的新业务规则先形成待确认问题，得到明确答复后再编码。
- 不修改无关模块，不保留废弃兼容逻辑，不直接修改第三方依赖目录。
- 阶段完成不等于生产交付完成；只有外部生产配置、备份恢复演练、权限验收、安全检查和全量回归全部通过后，才能判定达到生产交付标准。
